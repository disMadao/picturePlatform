### 图片列表缓存工程化实现说明（picture-backend）

本说明覆盖 `POST /picture/list/page/vo` 的图片列表缓存方案。目标是：在“可接受一定不一致”的前提下，做到稳定命中、可控失效、可观测、可扩展，适配多实例部署与高并发读场景。

---

### 1. 整体架构（双层缓存 + 版本号命名空间）

**读路径：**  
L1 本地缓存（Caffeine） → L2 Redis → DB → 回填 L2/L1  

**写路径：**  
写库成功后仅 **bump 版本号**，旧 key 自动失效（避免“多条件列表 key 无法精确删除”的问题）。

---

### 2. 关键问题与工程化处理

#### 2.1 一致性与失效
- **多条件列表**无法逐 key 删除，使用 **版本号命名空间**：`list:version` 变更后新 key 自动生效。
- 写库成功后再 bump，保证“写后必定能读到新版本命名空间的数据”。

#### 2.2 权限/可见性
- 缓存 key 需要覆盖 **空间维度**与**公开/私有规则**，避免“用户权限变化导致读到不该看的内容”。
- 对私有空间列表，接口仍执行权限校验，只缓存已通过权限校验的结果。

#### 2.3 缓存穿透与击穿
- **穿透**：对空结果做短 TTL 缓存（如 30-60s），防止重复回源。
- **击穿**：使用 “单飞” 控制（local lock / Redis mutex）避免大量并发同时回源。

#### 2.4 序列化与类型安全
- 使用 `TypeReference<Page<PictureVO>>` 进行反序列化，避免 `Page.class` 丢失泛型信息。
- 统一序列化配置，避免字段变化导致缓存解不出。

#### 2.5 观测与降级
- 记录 L1/L2 命中率、回源次数、平均回源耗时、缓存大小。
- Redis 异常时自动降级到 DB，保证可用性。

---

### 3. 缓存 Key 设计

**版本号 + 作用域 + 查询条件哈希：**

```
{prefix}:v{version}:{scope}:{md5(queryJson)}
```

- `prefix`：`yupicture:listPictureVOByPage`
- `version`：`yupicture:picture:list:version`
- `scope`：
  - 公共图库：`public`
  - 私有空间：`space:{spaceId}`

> 这样即使是私有空间，也可以做到“只失效该空间范围内的列表缓存”。

---

### 4. 核心代码（精简版，可直接落地）

#### 4.1 缓存 Key 工具

```java
public final class PictureListCacheKeys {
    public static final String LIST_CACHE_VERSION_KEY = "yupicture:picture:list:version";
    public static final String LIST_CACHE_KEY_PREFIX = "yupicture:listPictureVOByPage";

    public static String buildKey(String scope, String queryJson, long version) {
        String md5 = DigestUtils.md5DigestAsHex(queryJson.getBytes(StandardCharsets.UTF_8));
        return LIST_CACHE_KEY_PREFIX + ":v" + version + ":" + scope + ":" + md5;
    }
}
```

#### 4.2 版本号获取与 bump

```java
public class PictureListCacheVersionService {
    @Resource
    private StringRedisTemplate stringRedisTemplate;

    public long getVersion() {
        String v = stringRedisTemplate.opsForValue()
                .get(PictureListCacheKeys.LIST_CACHE_VERSION_KEY);
        if (v == null) {
            stringRedisTemplate.opsForValue()
                    .setIfAbsent(PictureListCacheKeys.LIST_CACHE_VERSION_KEY, "1");
            return 1L;
        }
        return Long.parseLong(v);
    }

    public void bumpVersion() {
        stringRedisTemplate.opsForValue()
                .increment(PictureListCacheKeys.LIST_CACHE_VERSION_KEY);
    }
}
```

#### 4.3 缓存读取（L1 -> L2 -> DB）

```java
public Page<PictureVO> getListPageWithCache(PictureQueryRequest req, HttpServletRequest request) {
    String scope = buildScope(req); // public / space:{spaceId}
    String queryJson = JSONUtil.toJsonStr(req);
    long version = versionService.getVersion();
    String cacheKey = PictureListCacheKeys.buildKey(scope, queryJson, version);

    // L1
    String cached = localCache.getIfPresent(cacheKey);
    if (cached != null) {
        return JSONUtil.toBean(cached, new TypeReference<Page<PictureVO>>() {}, true);
    }

    // L2
    cached = stringRedisTemplate.opsForValue().get(cacheKey);
    if (cached != null) {
        localCache.put(cacheKey, cached);
        return JSONUtil.toBean(cached, new TypeReference<Page<PictureVO>>() {}, true);
    }

    // 单飞控制，避免击穿
    return singleFlight(cacheKey, () -> {
        Page<Picture> picturePage = pictureService.page(new Page<>(req.getCurrent(), req.getPageSize()),
                pictureService.getQueryWrapper(req));
        Page<PictureVO> voPage = pictureService.getPictureVOPage(picturePage, request);

        String value = JSONUtil.toJsonStr(voPage);
        int ttl = voPage.getRecords().isEmpty() ? 30 : (300 + RandomUtil.randomInt(0, 300));
        stringRedisTemplate.opsForValue().set(cacheKey, value, ttl, TimeUnit.SECONDS);
        localCache.put(cacheKey, value);
        return voPage;
    });
}
```

#### 4.4 写后失效（版本 bump）

```java
// 在上传/编辑/删除/审核成功后调用
@TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
public void onPictureChanged(PictureChangedEvent event) {
    pictureListCacheVersionService.bumpVersion();
}
```

> 使用事务事件确保“写库成功 → 再失效缓存”，并适配多实例。

---

### 5. 触发版本 bump 的写接口范围

凡是影响“列表能展示的内容”的写操作，都必须 bump：

- 图片上传（本地/URL/批量）
- 图片编辑/更新（管理员）
- 图片删除
- 图片审核状态变更
- （可选）空间可见性变更

---

### 6. 工程化细节（落地要点）

- **权限校验必须先于缓存写入**，避免把“无权限结果”写入公共缓存。
- **缓存 value 尽量保持稳定字段顺序**（避免 json 变动导致热点频繁失效）。
- **监控指标**：L1/L2 命中率、回源 QPS、Redis 超时、缓存条数。
- **降级策略**：Redis 异常时直接回源 DB，不影响核心链路。

---

### 7. 小结

该方案对“多条件列表 + 轻度不一致可接受”的业务最合适：  
**读性能稳定、写后失效成本低、易扩展到多实例部署**，并且对既有代码侵入性小。
